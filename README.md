# 墨小七（QPoll Lite）

用手机 NFC 直刷四色墨水屏手机壳的安卓 App。从 [QPollLab](https://github.com/yhl88890/huawei-nfc-eink-myron) 改造分支演进而来，本仓库是独立精简版：前台直连、零特权优先、设备画像双路适配。

## 功能

- **选图 → 手动裁切 → 出图 → NFC 刷屏** 全链路
- 裁切页：取景框固定 552:768（与屏同比例），图片单指拖动、双指捏合缩放；默认铺满（与自动裁切一致），缩小可做留白构图，白边会真实进入画面（所见即所得）
- 四档出图风格，移植自墨小佳（Reink Case）官方算法：鎏金 / 质感 / 色阶 / 水墨
- 每档实时显示**非白占比**（口径见下文「测量口径」）与屏型
- 预览从打包字节回读，所见即所发
- 相册选图（ACTION_PICK），两机统一大缩略图体验

## 核心发现

**1. 清晰度不是功率问题，是算法问题。**
早期社区（包括我们自己）都以为墨水屏壳刷不出清晰画面是手机 NFC 输出功率不够——实测推翻了这个结论：同一块屏、同一台手机，只换出图算法，清晰度立刻上一个台阶。真正的分水岭是**点撒在哪儿**：把照片主体推成大片纯白（不抖动 = 不闪 = 干净），只在五官、发丝这些真暗部留点。本项目四档算法移植自墨小佳（Reink Case）官方 App，提取自其 Flutter debug 构建并逐行复刻；对传统「全图均匀抖动」是代差级的清晰度提升（对比与原理见 `ReinkRaster` 源码注释）。

**2. 起决定性作用的是 NFC 控制器芯片，不是手机，更不是功率。**
前辈们长期把刷屏失败归因于手机型号/输出功率；本项目双机对照研究明白：真正的变量是 **NFC 控制器芯片**——NXP SN100U 与 SN220U。K90 Pro Max 和 Note 12T Pro 的刷屏差异全部来自这两颗芯片的供能特性相反（大线圈「装死屏」vs 小线圈「活屏」，详见下表与源码注释），一套参数不可能通吃，这是设备画像双路分支存在的原因。手机 SoC、品牌、Android 版本本身都不是决定项；芯片同族 + ROM 未深度魔改的机型，理论上都能跑。

**3. Note 12T Pro 一类是零特权。**
不 root、不装 Shizuku、不给 adb 授权——App 前台 + 反射隐藏接口就能完整刷屏（杀 Shizuku、清 KernelSU 授权、重装 APK 后连刷实测通过）。与 Note 12T Pro 芯片同族（SN100U）的机型大概率同样零特权直跑，无需任何折腾。

最干净的证据链：`adb uninstall` → 全新安装（所有运行时授权与 appops 清零）→ 全程不执行任何 `pm grant` / `appops set` / Shizuku 授权 → 直接贴屏刷图成功。日志里 Q-Poll 开关由**本进程自己发出**（`QTAG_ON … 返回 0（接受）`），Shizuku 进程当时根本没在运行，KernelSU 模块列表里也没有任何 NFC 相关模块。

⚠️ 注意区分：`adb install` 是**电脑把安装包推给手机**，它不等于给 App 授予系统权限。「用 adb 装了包」和「App 运行时需要 adb 权限」是两件事。

**4. `68CA`（低电压）是屏内升压取电不足——物理层问题；软件的错误处理方式决定了它报不报、多久报一次。**

这一条最值得后来者看，因为社区（包括我们自己早期）几乎全都把它读成「电压不足 / 手机功率不够」，于是去换大功率手机——方向全错。10-31 凌晨 8 份日志全量归因 + 双机 A/B 对照，把它彻底钉死：

**三因素相乘模型：物理贴合 × 场断不断 × 图像翻转密度。** 屏内升压电路从射频场现取电刷新，刷新启动瞬间电流是平稳期的十几倍；三样里任何一样不达标，屏内电容被拉穿，就是 `68CA`。

- **最硬的铁证**：墨小佳官方 App、官方参数、官方屏，在贴合差的大线圈上照样连报两次 `68CA`——物理问题不认软件。
- **第二铁证**：`100%` 像素翻转的纯黑图能刷成（纯色相邻像素不打架，翻转密度≈0，电流需求最小）——所以它跟「点数/图像复杂度」无关，跟「相邻像素往相反方向打多少架」有关。Atkinson 的价值就是把翻转密度永远压在安全线内（这就是"换算法后 68CA 消失"的真因）。

**`D4` 第 4 字节定案（协议层）**：`0x80` = 收到即回（不查电）；`0x00` = 真查电、刷完才回（官方模式，小线圈实测阻塞 17.95 秒）。**贴合差时 `0x00` 会如实报 `68CA`，`0x80` 则不报**——双机 A/B：同屏同图同 500ms，`0x00` 在大线圈上报 `68CA`、小线圈阻塞 18 秒后 `9000`（总时长省 4 秒）。本项目默认 `0x80`，`0x00` 作为小线圈可选档保留。

**GitHub 原版（QPollLab）当年频报 `68CA` 的源码级真因**：D4 之后它每 500ms 发一条 `DE` 状态查询、**每条都过 `requireOk`**——屏升压电流高峰时被 DE 戳一下（传输+升压抢电），DE 回 `68CA`，`requireOk` 见 SW≠9000 直接抛异常中止整轮。**原版的 `68CA` 大多是它自己戳出来、然后自己判死的**；它还拿 DE 数据字节当忙闲信号（实测是恒定假信号）。本项目的 DE 保场**返回码一概不看**（喂场不查岗），连续 3 次发不出去才报中断。

解法组合拳（也是 `presence` 解法的上下文）：墨水屏整屏刷新需要**连续供能十几秒**，而 `enableReaderMode()` 默认每约 0.5 秒做一次在场检查，每次都让场中断一瞬——断一次就前功尽弃。小线圈（活屏）路把在场检查延时拉长：

```java
Bundle options = new Bundle();
// EXTRA_READER_PRESENCE_CHECK_DELAY 的常量值就是 "presence"（不是网传的 presence_check_delay）
options.putInt("presence", 90000);
nfc.enableReaderMode(activity, callback, FLAGS, options);
```

大线圈（装死屏，Android 16+）路恰恰相反：D4 后**干睡 20 秒、一条 DE 都不能发**——DE 喂场是小线圈的活命开关，却是大线圈的波形杀手（喂了反而"只闪一下"）。两路供能特性相反，这正是设备画像双路分支存在的原因。

⚠️ 另一个同样容易踩的坑：**`D4` 返回 `SW=9000` 只代表「指令被接受」，不代表刷完了。** D4 之后必须继续保场约 **20 秒**（或改用 `0x00` 让屏自己兜），否则画面会回滚成原样。

**5. 四色抖动算法已到实测上限，不必再折腾。**

屏是 2 bit/像素（只有黑、白、黄、红），照片是 24 bit，量化不可避免。我们把能想到的方案逐个实刷 / 1:1 像素比对了一遍：

| 方案 | 非白占比 | 结果 |
|---|---|---|
| **Atkinson 全四色（本项目「鎏金」档）** | **62%** | ✅ 最优，保留 |
| Bayer 8×8 有序抖动 | 74% | ❌ 8×8 阈值矩阵在 552×768 上重复 69×96 遍，肉眼可见横竖网格/布纹；发丝从点状颗粒变成线条感 |
| 蓝噪声 64×64（void-and-cluster） | 73% | ❌ 比 Bayer 更差，脸上大片发黄 |
| Floyd–Steinberg / Sierra-2 / Stucki | ~54% | ❌ 误差累积偏色，糊成一片黄 |
| 纯量化不抖动（＝「原图什么都不处理」） | 69% | ❌ 丝网印刷大色块，比 Atkinson 更糊、**而且更费电更热** |
| 降采样从面积平均换成 Lanczos | 62% | ❌ 1:1 像素下肉眼无差别 |
| 锐化（unsharp 0.8 / 1.2） | 62% | ⚠️ 只是略硬一点，提升可忽略 |
| 色相净化（低饱和区只允许黑白） | 59–62% | ❌ 阈值低无变化，阈值高丢大片中间层次成纯白 |
| 边缘感知（边缘区关掉误差扩散） | 63–68% | ❌ 边缘冒出黄红描边，比原方案更脏 |

根本原因：**四色最近色会把「中间调」判给黄色**（黄的亮度 205，比黑和红都更能代表灰）。抖动幅度一大，黄点就起来了，画面立刻网格化、发脏。Atkinson 只把 6/8 的误差传给邻居、**故意丢掉 2/8**，正好把这个毛病压住——这是它赢的**结构性原因**，不是参数调到位的运气。

一句话：想要「更清楚」，只能靠更多像素或更多颜色，那是硬件的事；算法侧到此为止。

## 测量口径：非白占比

早期版本这块的标签叫「翻转密度」，而且只统计纯黑像素（色码 0），把黄、红全漏了，数值跟肉眼对不上。现在统一改成**非白占比**：黑 / 黄 / 红 都算「要翻转、要上电」的像素，只有纯白不计。

```java
if ((codes[i] & 3) != 1) lit++;   // 1 = 白；只有白不算
```

参考值（真人照片，552×768）：鎏金 **62%**（黑 55 / 白 38 / 黄 3.5 / 红 4.0）。

## 双机验证

| 机型 | NFC 控制器 | Android | 权限路径 |
|---|---|---|---|
| Redmi Note 12T Pro | NXP SN100U（小线圈屏） | 15 | **零特权**：前台 + 反射隐藏接口 |
| Redmi K90 Pro Max | NXP SN220U（大线圈屏） | 17 | 前台 + 公开 vendor NCI API（需 `WRITE_SECURE_SETTINGS`，用 Shizuku 或 adb 授予；**不需要 root**） |

设备画像按 `SDK_INT` 分路（36+ 为「装死屏」路：收尾全断场 + D4 后干睡保场；35 为「活屏」路：踢遗留 + 保场 + DE 喂场）。两路的供能特性相反——DE 喂场是小线圈的活命开关，却是大线圈的波形杀手，详见源码内注释与实验记录。
